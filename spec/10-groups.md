# 10. Группы

Группа живёт в двух режимах. Попарный: сообщение уходит копией в каждую парную сессию, тем же `Encrypted`, что и личный чат. Кто вскрыл одну пару, читает копии, которые шли в эту пару. MLS: текст группы — один ciphertext OpenMLS, один и тот же каждому члену. Голос и файлы в обоих режимах остаются попарными, у каждой пары свой `transfer_id`.

Режим выбирается при создании. MLS — только если каждый выбранный член уже объявил в Hello бит `8` (`HELLO_CAP_MLS`). Иначе группа попарная. Позже попарную группу в MLS не переводят. В MLS-группу не добавляют того, кто бит не объявил. Диспетчер MLS не говорит: кадры идут от участника к участнику по `/void/chat/1.0.0`.

## Имя

`group_id` — 32 hex-символа (16 случайных байт), одно на все копии. В JSON сообщения поле `group_id`. Пока получатель не в составе, сообщение группы он не хранит. Пока отправитель, указанный подписью сессии или конверта, не в составе — тоже.

Вложение голоса в группе: у каждой пары свой `transfer_id`. Общий 16-байтный id в ленте, на проводе к участнику P:

```
BLAKE2b-128( "VOID_GROUP_VOICE_V1" || base[16] || P.to_bytes() )
```

первые 16 байт BLAKE2b. Файл к каждому члену — свой `Offer`/`VfC1` ([04-attachments.md](04-attachments.md)).

## Состав

Команда внутри ratchet или тело конверта `kind = group_sync`:

```
{
  "kind": "group_sync",
  "group_id": "<32 hex>",
  "group_name": "<1..128 байт>",
  "creator_id": "<PeerId>",
  "members": [ { "peer_id", "display_name" }, … ],
  "version": <u64>,
  "sig": [<байты>],
  "creator_pubkey_pb": [<protobuf или пусто>],
  "mls": <bool>
}
```

`mls` отсутствует у старого кадра и читается как false.

Членов не больше 256. Имя не пустое.

Подпись создателя, если `version > 0`:

```
"VOID_GROUP_SYNC_V1\0"
|| u16le(len(group_id)) || group_id
|| version_le_u64
|| u16le(len(name)) || name
|| u32le(count)
|| для каждого члена, по sort(peer_id, затем display_name):
     u16le(len(peer_id)) || peer_id
     u16le(len(display_name)) || display_name
```

`u16`-длины обрезают поле до 65535 байт; имя и так короче. Порядок в JSON на подпись не влияет: перед подписью члены сортируются. Если `mls` истинно, в конец этих байт дописывается один байт `0x01`. У попарной группы подпись этим байтом не кончается. Ключ — транспорт создателя ([01-identity.md](01-identity.md)). `sig` длиннее 256 или protobuf длиннее 4096 — подпись неверна.

Правила приёма:

- Новую группу записывает только кадр, чей отправитель сессии (или подписавший конверт) равен `creator_id`.
- `creator_id` существующей группы не меняется.
- Подписанный кадр создателя применяется только если `version` строго больше локальной и подпись верна. Старая версия группу назад не откатывает.
- Кадр создателя без подписи или с `version == 0`, когда группа уже известна, не двигает состав.
- Любой другой член может только добавить себя, убрать себя и сменить своё `display_name`. Чужие строки в его списке игнорируются. Версию он не увеличивает.
- Пустое имя в кадре создателя не затирает уже известное имя.

Уход и роспуск, отдельными кадрами:

```
{ "kind": "group_leave", "group_id", "peer_id" }
{ "kind": "group_delete", "group_id" }
```

`group_leave` применяет сам уходящий (`peer_id` равен отправителю кадра) или создатель. `group_delete` — только создатель известной группы.

Приглашение в тексте сообщения — строка, не отдельный поток:

```
void://group/<32 hex>?name=<urlencoded>&m=<peer>,<peer>,…&creator=<peer>
```

У MLS-группы в конец ссылки дописывается `&mls=1`.

Она едет внутри уже закрытого `text`. Кто не в паре, ссылку не читает. Разбор ссылки не заменяет `group_sync`: состав с `version > 0` принимает только подпись создателя. Автоматически вступать по одной ссылке участник не обязан; текущие участники по одной ссылке не вступают.

Офлайн-копия — конверт `group` или `group_sync` на каждого члена ([05-envelope.md](05-envelope.md)). Диспетчер видит N ящиков, не группу.

## MLS

Набор: `MLS_128_DHKEMX25519_AES128GCM_SHA256_Ed25519` (OpenMLS, RustCrypto). Credential — basic, байты строки `PeerId`. `group_id` на проводе — те же 32 hex.

Кадры на `/void/chat/1.0.0`, не внутри ratchet:

```
MlsKeyPackage { group_id, body }
GroupMls      { group_id, epoch: u64, body }
```

`body` — TLS-кодировка OpenMLS, не длиннее 256 КиБ. `MlsKeyPackage` шлёт входящий создателю: один key package на одно вступление. Создатель отвечает `GroupMls`: Welcome — этому входящему, Commit — остальным членам. Текст — тоже `GroupMls`, один ciphertext на эпоху, те же байты каждому члену отдельным запросом. `epoch` в кадре — номер эпохи отправителя. Повтор того же Commit получатель не применяет. Повтор текста запечатывает новое поколение, старый ciphertext второй раз не шлётся.

`group_sync` остаётся списком членов и подписью создателя. В дерево MLS член попадает Welcome и Commit, не этим JSON. Уход: `group_leave` как раньше. Свой Commit перед удалением состояния уходящий не шлёт. Создатель, увидев `group_leave`, коммитит удаление и рассылает Commit. Состояние ушедшего следующий epoch не открывает.

Снимок storage OpenMLS — локальное поле vault, на провод не выходит.

| Наблюдатель | Видит | Не видит |
|-------------|-------|----------|
| Член попарной группы | состав, имя, `version`, подпись создателя, текст тех копий, что пришли в его пару | кадры чужих пар |
| Член MLS-группы | состав, имя, `version`, один ciphertext эпохи и его открытый текст | секрет эпохи после своего удаления |
| Бывший член попарной группы | то, что успел расшифровать, пока был в паре | новые ключи пар, если пара после выхода сменила DH и старые `MK` стёрты |
| Бывший член MLS-группы | открытый текст эпох, которые он ещё держал | ciphertext следующих эпох |
| Диспетчер ящика | N конвертов v3 разным `recipient` | что это одна группа, имя, состав |
| Диспетчер circuit | несколько circuit от отправителя к членам, если так разошлась копия | JSON `group_sync` |
| Узел DHT | ничего о группе | `group_id`: в DHT его нет |
