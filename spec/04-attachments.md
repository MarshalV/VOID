# 04. Вложения

Файл и голос не едут отдельным смыслом. Байты закрыты тем же Double Ratchet, что и чат, и лежат в `Encrypted` на `/void/chat/1.0.0`. Пузырь в ленте — JSON сообщения с `file` или `voice` ([03-session.md](03-session.md)); он ссылается на `transfer_id` из 16 байт, на проводе как 32 hex в нижнем регистре.

`/void/file/1.0.0` — запасной канал только к участнику, с которым уже есть прямое соединение. Там JSON управления. Чанки новых участников по этому потоку не идут.

## Кадр чанка `VfC1`

Открытый текст ratchet, не JSON (не начинается с `{`):

```
"VfC1" || transfer_id[16] || chunk_index_le_u32 || data
```

`data` одного чанка — до 32 КиБ. Последний чанк короче. Число чанков:

```
0                         если size = 0
ceil(size / 32768)        иначе
```

Размер файла — до 512 МиБ, включая 0 байт. Индекс с нуля.

Целостность файла — BLAKE2b-512 всего файла, на проводе первые 32 байта. Поле в оффере исторически называется `sha256`. Это не SHA-256. Получатель сверяет эти 32 байта после сборки. Для голоса `voice_ack` с `ok: true` уходит только после совпадения.

## Кадр управления `VfP1`

```
"VfP1" || json
```

`json` — один из вариантов `FilePacket` (внешний тег serde):

| Вариант | Поля |
|---------|------|
| `Offer` | `transfer_id[16]`, `filename`, `total_size`, `total_chunks`, `sha256[32]`, `kind` |
| `Accept` | `transfer_id` |
| `Reject` | `transfer_id`, `reason` (≤ 512 байт) |
| `Cancel` | `transfer_id` |
| `Request` | `transfer_id` — прислать заново |

`kind` оффера: `Image`, `Audio`, `Other`. Имя файла в оффере — до 512 байт. Получатель отвергает оффер, если `total_chunks` не сходится с `total_size` и шагом 32 КиБ, или `total_size` > 512 МиБ.

Порядок. Отправитель шлёт `Offer`. Получатель отвечает `Accept` или `Reject`. Чанки идут после `Accept`, по одному, каждый следующим кадром ratchet. `Cancel` может прислать любая сторона.

Через circuit отправитель не чаще примерно 64 КиБ/с (пауза между чанками не меньше `32768 * 1000 / 65536` мс). Это поведение отправителя, не поле кадра. Прямое соединение может слать быстрее; минимум между чанками на практике 5 мс.

## Запасной `/void/file/1.0.0`

Тот же JSON `FilePacket`, но открытым текстом внутри Noise этого потока (не внутри ratchet). Чанк-вариант:

```
Chunk { transfer_id[16], chunk_index, data }
```

`data` не длиннее 32 КиБ. Новый отправитель так не шлёт: чанк только `VfC1`. Приёмник ещё принимает `Chunk` от старого участника. `Ack` на этом потоке — юнит-вариант, JSON-строка `"Ack"`.

Имя, размер и 32 байта BLAKE2b на `/void/file` видны тому, кто терминирует Noise, то есть собеседнику. Диспетчер circuit их не видит: поток внутри circuit — Noise двух участников.

Голос — тот же файловый путь, `kind = Audio`, имя `void_voice_<32 hex>.wav`. В JSON чата дополнительно `voice.duration_secs`. Автоприём голоса — решение участника, не отдельный байт.

Офлайн-голос, когда circuit нет, режется в конверты `voice_chunk` ([05-envelope.md](05-envelope.md)), а не в `VfC1`.

| Наблюдатель | Видит | Не видит |
|-------------|-------|----------|
| Собеседник | имя, размер, вид, хэш, чанки после ratchet | чужой локальный путь |
| Диспетчер circuit | объём потока | `VfP1`, `VfC1`, имя, хэш |
| Диспетчер ящика | конверт v3 и его бакет, если файл ушёл офлайн-голосом | WAV: он внутри `ct` |
| Узел DHT | ничего от файла: байты файла в DHT не пишутся | файл |
