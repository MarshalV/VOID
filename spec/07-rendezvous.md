# 07. Встреча (Hop)

Двое за NAT не слышат друг друга напрямую. Диспетчер даёт им circuit. Это libp2p Circuit Relay v2, не отдельный кадр VOID.

| Поток | Направление | Зачем |
|-------|-------------|--------|
| `/libp2p/circuit/relay/0.2.0/hop` | участник → диспетчер | резервация: «держи для меня вход» |
| `/libp2p/circuit/relay/0.2.0/stop` | участник → диспетчер → участник | сам circuit |

Резервация — сообщение HOP `RESERVE`. Успех — статус, который libp2p зовёт принятой резервацией. До этого успеха участник через этого диспетчера не набирается: адрес вида

```
<публичный multiaddr диспетчера>/p2p-circuit
```

ещё не вход. Слушатель участника на этом адресе без принятой резервации не считается встречей.

Чужой участник набирает

```
<multiaddr диспетчера>/p2p-circuit/p2p/<PeerId назначения>
```

только после своей принятой резервации на том же диспетчере. Иначе резервация и второй набор делят один TCP и оба падают.

Внутри принятого circuit — обычные Noise и yamux **двух участников**. Диспетчер пересылает байты circuit и не является стороной Noise.

## Сколько держит диспетчер

Иначе двое за одним NAT не проходят значения по умолчанию relay (короткий circuit, жёсткий лимит с одного IP):

| Предел | Значение |
|--------|----------|
| резерваций всего | 1024 |
| резерваций на один `PeerId` | 32 |
| circuit всего | 256 |
| circuit на один `PeerId` | 32 |
| длина одного circuit | 1 час |
| байт на один circuit | 64 МиБ |

Отдельный лимит «одна резервация в минуту с IP» диспетчер VOID не включает: за одним адресом часто два участника. Превышение пределов — отказ резервации или circuit по статусу relay, не кадр `/void/chat`.

Один диспетчер на circuit видит оба `PeerId`. Это и есть встреча. Onion ([09-onion.md](09-onion.md)) — другой жест: размазать эту пару по нескольким диспетчерам. Пока Hop один, пара видна ему.

## `DialBack`

Если A достучался до B, а B до A нет, A по уже живой сессии (кадр ratchet, не onion) шлёт:

```
DialBack { circuit_addrs: [ "<relay>/p2p-circuit/p2p/<A>", … ] }
```

B набирает только те адреса, которые содержат `p2p-circuit` и чей relay входит в известный B набор диспетчеров. `DialBack` с диспетчера, из onion или без живой сессии B не исполняет. Диспетчер, получивший `DialBack` как обычный запрос чата, отвечает `Ack` и никого не набирает: это подсказка участнику, не команда узлу.

Пока резервации нет, участник не шлёт диспетчеру пачку `Store` вперемешку с HOP так, чтобы забить поток резервации. Письмо может подождать. Это не меняет байты `Store`.

| Наблюдатель | Видит | Не видит |
|-------------|-------|----------|
| Диспетчер Hop | `PeerId` резервации, пару circuit, числа байт, время жизни | кадры Noise, `Hello`, текст, файл |
| Участник A | свой circuit к B и факт, что резервация принята | IP B, если B пришёл только через circuit |
| Наблюдатель одного TCP к диспетчеру | IP этой стороны и размеры | вторую сторону, если она на другом соединении; пару он видит только на самом диспетчере |
| Диспетчер, увидевший `DialBack` | что запрос был (если это не внутри чужого circuit) | не получает обязанности набирать адрес |
